### 1.2 数据集获取（绕开网络限制）

服务器只能访问国内站点（GitHub、HuggingFace 均不可达），Google Drive 也不通。
最终的解法是在 **ModelScope 找到官方 RadioMapSeer.zip 的镜像**
（`Hzzzz001/radiomapseer`，3.14 GB，SHA256 与官方一致），直接从服务器拉取，
平均 900 KB/s，耗时约 55 分钟。

```
https://www.modelscope.cn/api/v1/datasets/Hzzzz001/radiomapseer/repo?Revision=master&FilePath=RadioMapSeer.zip
```

**这个镜像的实际目录结构与常见文献描述不一致**，值得记录：

```
RadioMapSeer/
├── gain/gain/carsDPM/<city>_<tx>.png    56080 张 DPM gain（city 0..700, tx 0..79）
├── gain/gain/carsIRT4/<city>_<tx>.png   1402 张
├── gain/antenna/<city>.json             80 个 Tx 坐标
├── png/buildings_complete/<city>.png    701 张建筑图
├── png/antennas/<city>_<tx>.png         每个样本一张「单 Tx」图
└── png/{cars,roads,buildings_missing1-4,...}
```

两个坑：

1. **索引从 0 开始**（city 0–700、tx 0–79），不是 1–701。
2. `gain/antenna/<city>.json` 里的坐标**顺序与 tx id 不对应**。实测
   `json[0] = [108, 68]`，但 `antennas/0_0.png` 的亮点在 `(row=187, col=108)`。
   因此放弃用 json 取坐标，改为**直接读 gain 图的 argmax**：

   ```
   argmax(gain map) == png/antennas/<city>_<tx>.png 的唯一点亮像素
   ```
   抽样验证 3 组全部吻合，顺带省掉了对 56080 张 antenna 图的读取。

### 1.3 预处理

按论文：路径损耗 $[-127,-47]$ dB 线性映射到 $[0,1]$（等于 `raw/255`），
低于 0.2 的像素置零，剩余值再用 $(x-0.2)/0.8$ 拉回 $[0,1]$。

结果缓存成 npy：

| 文件 | 形状 | 大小 |
|---|---|---|
| `gain_dpm.npy` | (56080, 256, 256) uint8 | 3.5 GB |
| `buildings.npy` | (701, 256, 256) uint8 | 44 MB |
| `tx_coords.npy` | (56080, 2) int16 | 220 KB |

**数据正确性验证**（这一步不能省）：

- 抽查 6 个样本，Tx 位置**全部落在建筑之外**（10/10 正确）；
- 强信号（gain>128）与建筑像素的重叠率仅 **0.001**，说明信号确实沿街道传播，
  建筑图与信号图空间对齐无误；
- 训练/验证/测试的 target 均值分别为 0.118 / 0.085 / 0.141。

## 2. 实现要点

| 模块 | 文件 | 说明 |
|---|---|---|
| 双编码器 U-Net + AFM | `src/models.py` | 标准五级 U-Net（32/64/128/256/512），AFM 在每个 stage 融合 |
| 图精修网络 | `src/models.py` | patch embedding(×4 stride2) → KNN(k=16) → 3 层 MRConv → Graph2Image(×4) |
| 复合损失 | `src/losses.py` | $0.1\,\mathcal{L}_{coarse} + \mathcal{L}_{refine} + 10^{-4}(1-\text{MS-SSIM})$ |
| MS-SSIM | `src/losses.py` | 自实现（5 尺度、11×11 高斯窗），不依赖第三方包 |
| 数据管道 | `src/dataset.py` | 三种采样设置、观测点抽取、增强 |
| 训练 | `src/train.py` | AMP、梯度裁剪、多步学习率衰减、best 权重 |

自检（`src/selftest.py`）确认：24.55 M 参数、输出形状正确、反向传播正常、
MS-SSIM 实现无误（自比 = 1.0000，与随机图 = 0.2205）。

**性能基准**：bs=32、AMP，0.247 s/iter，峰值显存 8.87 GiB → 5.1 min/epoch
（纯计算），实测含数据加载约 5.5 min/epoch。

## 3. 排查记录：为什么复现结果远低于论文

### 3.1 现象

第一轮按论文设置训练（50 epoch 计划），到第 4 个 epoch 时：

| 指标 | 数值 |
|---|---|
| 训练集 NMSE | ≈ 0.011 – 0.026 |
| 验证集 NMSE | 0.247（ep1 0.251 → ep2 0.301 → ep3 0.247 → ep4 0.248） |
| 论文报告（test） | 0.0043 |

训练集与验证集相差约 **20 倍**，且验证曲线在 0.18–0.42 之间反复震荡。

### 3.2 逐项排除

| # | 假设 | 验证方式 | 结论 |
|---|---|---|---|
| 1 | 建筑图与 gain 图错位 | 抽查 Tx 是否在建筑内、强信号与建筑重叠率 | **排除**，重叠率 0.001，Tx 全部在建筑外 |
| 2 | city id 与建筑数组索引错位 | 检查 `buildings_city.npy` 与 `city_to_bidx` | **排除**，索引严格为 0..700 |
| 3 | BatchNorm 的 running stats 与验证分布不匹配 | 分别用 eval / train 模式评估同一权重 | **排除**，train 模式更差（0.32 vs 0.26） |
| 4 | 训练不足（只跑 4–5 epoch） | 跑到 10 epoch | 曲线在 0.18–0.42 震荡，**无明显收敛趋势** |
| 5 | 模型过参数化（24.55 M 对 4 万样本） | 窄模型 14.96 M 对照 | **无改善**（0.234 vs 0.251） |
| 6 | AFM 的通道 softmax 压制环境分支 | 换 sigmoid 门控 | **无显著改善**（0.249 vs 0.252） |
| 7 | 缺数据增强 | 加翻转/转置增强 | **无改善**（0.270 vs 0.251） |
| 8 | 每 epoch 重采观测点导致输入分布漂移 | `--fixed-obs` 固定观测 | **排除**，仍然震荡（0.183→0.226→0.178） |
| 9 | 观测点浪费在无信号区（56% 落空） | `--obs-on-signal` 仅在信号区采样 | **小幅改善约 20%**（0.218 vs 0.272） |
| 10 | 预测幅度整体偏移 | 线性校准 $a\cdot p+b$ | **排除**，标定系数 a=0.97，校准后 NMSE 几乎不变 |
| 11 | 模型没学到空间结构 | 计算预测与真值的相关系数 | **排除**，corr = 0.65–0.88，结构是对的 |

### 3.3 得到的关键认识

**（1）验证集恰好是最难的一档，一直盯 val 会严重低估结果**

| 划分 | target 均值 | 观测点非零比例 | NMSE（单编码器 5 epoch） |
|---|---|---|---|
| train | 0.118 | 0.590 | 0.026 |
| val | 0.085 | 0.443 | 0.206 |
| **test** | **0.141** | **0.652** | **0.087** |

验证集的信号覆盖率明显低于训练集和测试集，模型在它上面表现最差。
论文报告的是 test，所以判断进展必须以 test 为准。

**（2）误差性质：幅度被平滑，不是找不到位置**

可视化显示预测的亮区位置与真值一致（corr 0.75–0.88），误差集中在发射机附近的
高值区，表现为「预测偏低」。这是 MSE 回归的典型回归到均值现象，而不是模型
完全没学会。

**（3）观测点采集策略的影响被低估**

论文只写了 "randomly distributed over the entire radio map"，没有说明是否
允许落在无信号区域。实测全图均匀采样时约 56% 的传感器读数接近零（相当于浪费），
改成仅在信号区布点后 val NMSE 改善约 20%。这是论文未着墨但影响明显的细节。
