**U-Net 的干净重训结果值得单独记一笔**：50 轮、论文口径、测试集
8080 张，NMSE 0.00583 / RMSE **0.02002**，最优轮次第 47 轮。
论文 U-Net 是 0.0182，偏差 **+10%**，属于正常复现误差范围。
这是目前唯一一个「完全按论文协议跑完」的对照模型，可信度最高。

**还没做出来的：** DeepAE、RadioUNet、Pix2pix+、RME-GAN。
模型代码已写完并验证过前向 shape，已排进 gpu0 的串行链，等前面跑完。

**第一个明显的异常：U-Net 比完整模型还好（0.0196 对 0.0211）。**
论文里是反过来的（0.0150 对 0.0182）。原因大概率是训练轮次不一致
（U-Net 停在第 26 轮，完整模型停在第 20 轮），也可能是复现的多模态融合
部分确实没起到作用。等新的完整模型跑完再定论。

### ② 盲区专项分析

论文要看的是：误差到底堆在盲区边缘，还是摊在盲区深处。

我把盲区里的每个像素按"离最近可见区的距离"分成六档，分别统计误差。
中等盲区下的完整模型：

| 离边界距离 | 1-2 px | 2-4 | 4-8 | 8-16 | 16-32 | 32+ |
|---|---|---|---|---|---|---|
| RMSE | 0.0220 | 0.0226 | 0.0237 | 0.0260 | 0.0297 | 0.0332 |

**读数：误差是随深度单调上升的，从边界往里涨了 50%。**

这和论文的说法不完全一样。论文说"误差集中在建筑边缘，不在盲区内部"，
我这边看到的是越往盲区中心越差——这其实是更符合直觉的结果（离观测点
越远越不准）。要下结论得等完整模型重训完重画一遍，现在的图在
`fig_gap.png`。

### ③ 消融验证（论文表 V）

八个变体全部重评完毕：

| 变体 | 均匀场景 | 中等盲区 | 大盲区 |
|---|---|---|---|
| 完整模型 | 0.0211 | 0.0222 | — |
| 换融合：拼接 | 0.0191 | 0.0325 | 0.0328 |
| 换融合：相加 | 0.0243 | 0.0341 | 0.0208 |
| 换融合：sigmoid 门控 | 0.0185 | 0.0333 | 0.0396 |
| 换融合：交叉注意力 | 0.0293 | 0.0322 | 0.0362 |
| 去掉图卷积 | 0.0184 | 0.0252 | 0.0208 |
| 静态图（不自适应） | 0.0337 | 0.0198 | 0.0381 |
| 去掉残差 | 0.0392 | 0.0403 | 0.0407 |
| 单编码器 | 0.0196 | 0.0303 | 0.0259 |

**三个能站住的结论：**

1. **残差连接是命门。** 去掉之后三个场景全线崩到 0.039–0.041，是全场最差，
   比完整模型差 85% 以上。这一条和论文完全一致（论文说 NMSE 涨 5.4 倍）。
2. **图卷积分支在本复现里没带来收益，甚至有害。** 去掉它反而最好
   （0.0184，比完整模型还好 13%）；把动态图换成固定网格图在中等盲区也是
   最好的（0.0198）。论文认为动态图是核心创新，我这边看不到这个效应。
3. **融合方式里，sigmoid 门控优于论文的 softmax 门控**（0.0185 对 0.0211）。
   原因在代码注释里写过：softmax 沿通道归一化，512 个通道平均每个权重只有
   1/512，等于把环境分支整体压暗了。这可能是复现出来融合不如人意的直接原因。

**一个必须说明的限制：** 这些模型的存盘轮次大多是第 1–15 轮（不是训练到
收敛的第 50 轮），因为当时的早停看的是被污染的错误验证集。所以上面这些
数字是"同等条件下谁更好"的相对比较，绝对值不能直接对论文。

## 二、这一轮最重要的技术发现（口径问题）

旧的那批实验（24 个消融 + 5 个早期主线）训练时，把观测点**只放在有信号的
像素上**；论文的做法是在整张图上按密度均匀撒点。

我做了对照实验：同一份权重，两种撒点方式分别评估——

| 训练方式 | 均匀撒点 | 只放有信号处 |
|---|---|---|
| 均匀撒点训练 | 0.0177 | 0.0170 |
| 只放有信号处训练 | 0.0192 | 0.0175 |

**两种口径差 4–9%，不是数量级差异。**

结论：消融实验可以不重跑，只要在同一张表里注明"这批是另一种撒点方式"，
变体之间的相对排名仍然有效。省下来的显卡算力应该给 ① 里缺的那 5 个模型
——那才是真正的硬伤。

## 三、当前在跑（2026-11-04 17:25 更新：已改为全自动调度）

现在不需要人盯：三个调度会话 + 一个 cron 守护，任何一张卡空出来都自动接活。

| 层 | 机制 | 负责的内容 |
|---|---|---|
| `gpu0_chain.sh`（会话 gpu0） | 独占 gpu0 串行 | MFFGCN seed0 → sigmoid → spatial → DeepAE → RadioUNet → Pix2pix+ → RME-GAN |
| `queue.sh`（会话 w2/w3） | gpu2/gpu3 抢任务 | MFFGCN seed1–4、U-Net seed1–4 |
| `autopilot.sh`（会话 autopilot，新增） | 4 个 worker 轮询**任意**空闲卡 | 三场景对照表缺的 s2/s3：主模型、U-Net、DeepAE、RadioUNet、Pix2pix+、RME-GAN |
| `supervisor.sh` + cron 每 10 分钟（新增） | 会话守护 | 会话意外消失且仍有待办时自动拉起，只拉起不 kill |
| 集群 Slurm 队列 | 作业 22964–22967、22972–22975 | U-Net seed1–4 + 四个基线（s1），按调度自动开跑 |

**自动派发的安全设计**：空闲判据是「剩余显存 ≥ 34 GB + 利用率 ≤ 25% + 无我方进程」，
而且连续两次采样（间隔 40 秒）都通过才动手——实测主模型单 run 峰值占 26–34 GB，
阈值低了必然 OOM，而两次采样是为了避开别的 worker 两轮训练之间那几秒空档。
并发用 `runs/.gpulock_<gpu>`（记持有者 PID，worker 被杀可自动回收）+ `runs/.claim_<tag>`
两层原子锁，多 worker 不会挤同一张卡、也不会重复训练同一个任务。

**一眼看状态**：服务器上执行 `./status.sh`，显卡、进程、各 run 轮次与验证误差、会话、待办数量全部列出。

**排期说明**：四张卡里 gpu1 是别人的任务，gpu2/gpu3 各被占了 33–38 GB，
本模型在共享卡上从独占时的 323 秒/轮掉到 900–1000 秒/轮。按当前速度，
剩下 6 个种子 run + 3 个主线 run + 4 个基线 run 合计约需 **两天**。
集群要到 11/06 17:11 才可能排上第一个作业（40 GB 与 80 GB 两个分区目前都满）。
脚本全部幂等，随时中断重跑都会自动跳过已完成的。

## 四、2026-11-05 补充：盲区深度剖面已换成新权重（② 有数了）

之前 ② 那张六档表是旧权重算的，现在用修复坐标后的权重、全测试集 8080 张重算，
并把 U-Net 拉进来做同口径对照（`src/diag_depth.py` + `depth_sweep.sh`，
数据落在 `results/depth_s1.json`、`results/depth_single_s1.json`）。

| 离最近观测点 | MFFGCN | U-Net | 本文领先 |
|---|---|---|---|
| 1–2 px | 0.0112 | 0.0120 | 7% |
| 2–4 px | 0.0135 | 0.0144 | 6% |
| 4–8 px | 0.0155 | 0.0165 | 6% |
| 8–16 px | 0.0175 | 0.0189 | 7% |
| 16–32 px | 0.0203 | 0.0234 | 13% |
| 32+ px | 0.0241 | 0.0350 | 31% |

三个结论：

1. **「越深越差」在新权重上依然成立**，贴边到 32 px 外涨了 115%。
   整体 RMSE 0.01767 / NMSE 0.00454，与 `test_metrics.json`（0.01766 / 0.00454）
   对得上，说明这套分箱统计本身没算错。
2. **本文模型的优势随深度扩大**：贴边只领先 7%，深处领先 31%，相对优势涨了 4.7 倍。
   这比「整体赢 10%」更能说明多模态融合 / 图分支到底在哪儿起作用——
   不在边缘，在观测点够不着的深处。
3. 论文说「误差集中在阴影边缘」，与本复现的「随深度单调上升」方向相反。
   但两者描述的其实不是同一件事（形态 vs 位置），且论文没给同口径曲线，
   所以只能记成「论文没覆盖、我补上的观测」，不算反证。

待补：Setup 2 已于 12:29 开训、Setup 3 仍在排队，两套新权重都还没出来；
`depth_sweep.sh` 已留好入口（`runs/txf_mffgcn_s2|s3` 一出现，重跑脚本会自动补上这两条曲线）。

## 六、队列扩充：消融 s2/s3 重跑 + 鲁棒性（2026-11-05 21:35）

上一轮评估发现表 V 的 s2/s3 那 16 格全是坐标 bug 期的数据
（`runs/ab_*_s2` 的 NMSE 在 0.09–0.13，是修复后口径 0.0045 的 20 倍），
不能当论文绝对值用；鲁棒性一节则整个是空的。已把它们排进队列。

### 新增两套执行单元

| 会话 | 脚本 | 内容 | 数量 |
|---|---|---|---|
| `autopilot2` | `autopilot2.sh` | 主表剩余 5 格 + 消融 s2/s3 干净重跑 | 19 个训练 run |
| `robust` | `robust_eval.sh` | 噪声 SNR 30/20/10 + 观测数量 ×0.5/2/4，三个 setup | 21 次评估 |

两者都用 `runs/.gpulock_<gpu>` 原子锁和 `runs/.claim_<tag>` 抢占，
和原有 `autopilot` 共用同一套锁，不会同一张卡挤两个训练、也不会重复训练同一个 tag。

### 消融重跑的标签与参数

新标签 `txf_ab_<变体>_s{2,3}`，与旧的 `ab_*` 区分开，避免误判"已完成"。
参数沿用 `run_experiments.sh` 里的映射，但**去掉 `--obs-on-signal`**（论文口径是均匀撒点）：

| 变体 | 参数 |
|---|---|
| concat / add / sigmoid / cross | `--afm-mode <同名>` |
| nogcn | `--gcn-mode none` |
| static | `--gcn-mode static` |
| nores | `--no-residual` |

`autopilot2.sh` 为此把任务格式从 5 段扩到 6 段（`tag:arch:afm:setup:显存:额外参数`），
第 6 段可选，不填时行为和原来完全一致。

### 鲁棒性的口径修正

旧 `robustness.sh` 用的是 `runs/FINAL_s1/best.pt`（坐标 bug 期权重）且开了
`--obs-on-signal`，两个都和现在的口径不一致。新脚本改用
`runs/txf_mffgcn_s{1,2,3}/best.pt`、不加 `--obs-on-signal`；
哪个 setup 的权重先出来先评哪个，s2/s3 明天出权重后自动补上。
显存门槛设 22 GB，只在基本空的卡上跑，不去挤正在训练的任务。

### 排期

19 个训练 run 按共享卡 1180 s/轮 估，合计约 150 GPU·小时；
4 张卡并行约 **1.5–2 天**跑完。鲁棒性单次评估 8 分钟左右，
等第一张卡空出来（约凌晨 2:35）开始，3 个 setup 合计约 3 小时。
