--------------------------------------------------------------------------------
 0. 先看这里：四者关系
--------------------------------------------------------------------------------

    dataset.py  --样本-->  models.py  --预测-->  losses.py
         ^                                          |
         +---------- train.py 调度 / 反向传播 -------+

  dataset.py   决定输入长什么样
  models.py    决定能力上限
  losses.py    决定往哪个方向学
  train.py     决定能不能真的学会

  一次训练的实际数据流：

    DataLoader 取出 4 份张量 (obs / env / mask / target)
      -> MFFGCN.forward 得到 (coarse, fine, residual)
      -> MFFGCNLoss 算出标量总损失
      -> backward 回传梯度、更新参数
      -> 每个 epoch 在验证集上算 NMSE，更优就存 best.pt
      -> 训练结束，用 best.pt 在测试集上算最终指标

  效果不好时的排查顺序（成本从低到高）：
    train.py 的学习率与早停  ->  losses.py 的权重  ->  models.py 的结构

  只有一件事需要注意：这四个文件不是平级的。
  models.py 是论文正文，dataset.py 是实验环境，
  写报告时引用「方法」只引 models.py + losses.py，
  引用「实验设置」才引 dataset.py。

 1. dataset.py  —— 造数据（411 行）
--------------------------------------------------------------------------------

【它负责什么】
  把一张城市地图变成一份可训练的样本，做三件事：

    a) 读入建筑高度图（RadioMapSeer 数据集），仿真出真值覆盖图 target
    b) 根据 setup 决定「哪些位置允许测量」allowed
    c) 在允许区域内采样出「实际测了哪些点」obs_mask，
       再把真值乘上 obs_mask，得到稀疏观测图 obs

【关键定义】

  行  52   preprocess_gain()        uint8 灰度转成 [0,1] 的线性增益
  行  67   restricted_area_map()    生成受限测量区（缺测区域）
  行  98   square_window()          方形窗口，Setup 2 用
  行 118   two_side_densities()     两侧不同采样密度
  行 145   class RadioMapSeer       数据集主体
  行 163     __init__               split / setup / 各类变换参数
  行 228     set_epoch              每轮重新采样观测点（相当于数据增广）
  行 233     __len__
  行 236     _load_gain             读单张增益图（带缓存）
  行 246     __getitem__            一个样本的完整生成流程，重点看这里
  行 375   build_loaders()          按城市划分 train/val/test 并建 DataLoader

【四份张量】

  名称    形状              内容
  obs     (B,1,256,256)     稀疏观测，绝大多数像素是 0，只有测点非零
  env     (B,2,256,256)     第 0 层建筑高度，第 1 层发射机位置
  mask    (B,1,256,256)     0/1，表示这个点有没有真的测到
  target  (B,1,256,256)     真值覆盖图，作为监督信号

  256 是数据集栅格边长，1 像素约等于 1 米，即一个 256m x 256m 的区块。
  一个 batch（bs=32）的 obs 约 8 MB（fp32），四份合计约 40 MB。

  env 是唯一通道数为 2 的，所以模型里要 torch.cat([obs, env], dim=1)
  拼成 3 通道。这也是「双编码器」的物理起因。

【最关键的一组概念：allowed 与 obs_mask】

  allowed    「能测的区域」，由建筑遮挡和规则决定，与随机采样无关
  obs_mask   「实际测了的点」，是 allowed 的子集，每次采样都不同

  这两个概念一旦混用，Setup 2 和 Setup 3 就会写错：
  网络只应在 allowed 区域内学习先验，但损失要覆盖整张图。

【三种 Setup 的差别】

  s1  在允许区域内随机稀疏采样，采样率随城市变化
  s2  方形窗口：只在某个方形区域内密集测量，其余区域是盲区
  s3  冲激噪声：在 s1 基础上，部分测点带椒盐式错误值

  想改实验条件只改这个文件，models / losses / train 都不用动。
  反过来说，如果 setup 在这里被写错，后面所有数字都失去意义。

【为什么按城市划分数据集】
  按样本随机划分，会让同一栋楼、同一发射机的其它接收点漏进测试集，
  模型相当于「见过这栋楼」，指标会虚高 20% 以上。
  所以 build_loaders 是按城市切分的，这是复现论文数字的前提。

 2. models.py  —— 定网络（541 行）
--------------------------------------------------------------------------------

【它负责什么】
  论文的三个创新点全部落在这个文件里：

    1) 双编码器     稀疏观测与稠密环境分开编码，不共用 BN 参数
    2) 自适应融合   AFM，门控只作用在环境分支
    3) 图精修       GraphRefineNet 在粗估图上补残差

【主模型只有三步】（行 484 forward）

    coarse = self.fusion(obs, env)            ① U-Net 出粗估
    out    = self.refine(obs, coarse, mask)   ② 图网络算修正量
    fine   = coarse + out                     ③ 残差相加
    return coarse, fine, out

  三者都返回，因为损失要同时监督 coarse 和 fine；
  out 在消融里可以关掉（--no-residual），此时图分支必须从零画出整张图，
  难度显著更高，这是「w/o Residual」那一行的由来。

【关键定义】

  行  53   ConvBNReLU              卷积 + BN + 激活 的标准块
  行  64   EncStage                编码器一级：两次卷积 + 下采样
  行  83   DecStage                解码器一级：上采样 + 跳连拼接
  行 108   class AFM               自适应特征融合，七种模式
  行 187     forward              七种模式的分派逻辑
  行 234   class DualEncoderUNet   双编码器 U-Net
  行 280     forward              两路编码 -> 逐级融合 -> 解码
  行 309   class MRConv            多方向相对卷积
  行 331     forward              沿多个方向做差值再取 max
  行 348   class GraphRefineNet    图精修分支
  行 428     forward              切 patch -> 建图 -> 图卷积 -> 拼回
  行 463   class MFFGCN           主模型，只有三步
  行 484     forward              见上
  行 496   class SingleEncoderUNet 单编码器消融版
  行 539   count_params()         数参数量

【AFM 的七种模式】（--afm-mode 参数）

  softmax   论文默认。通道维 softmax 出权重（论文公式 4）
  sigmoid   每通道独立 0~1 门控
  spatial   在 H*W 维归一化，而不是通道维
  se        Squeeze-Excitation 式通道注意力
  concat    不加任何门控，直接拼接（对照组）
  add       直接相加（对照组）
  cross     交叉注意力：q 取观测全局均值，k/v 取环境逐像素

  Table V 的消融就是换这个参数，一共七列。

  一个必须知道的副作用：softmax 在 C=512 时，
  每个通道的平均权重只有 1/512，相当于把环境分支压平。
  这是论文原设计，代码保留了；spatial 模式就是为了对比这一点加的。

  另一个设计细节：所有门控都只乘在 f_env 上，不乘 f_obs。
  因为观测是真实测量，不该被网络削弱；环境只是先验，需要自适应调整。

【GraphRefineNet 怎么工作】

  1. 把 256x256 的图切成 patch=16 的小块，得到 16x16 = 256 个节点
  2. 每个节点用特征算 k 近邻（默认 k=16），建稀疏图
  3. 在图上做 gcn_layers 层传播（默认 3 层）
  4. 把节点特征铺回 256x256，与原图逐像素相加

  类比：把地图看成一张社交网络，每个 16x16 小块是一个用户，
  邻居之间互相传话，传几轮后每个块都掌握了周围的情况。

  Fig.13 的「传播步数」曲线改的是 gcn_layers，
  「邻居数」曲线改的是 k。

【MRConv 为什么取最大值而不是均值】
  无线电传播具有各向异性：穿墙、沿街方向场强变化剧烈，
  如果取均值，强边界会被抹平。取最大相对差才能保住这些边界。

【消融时这里怎么改】
  w/o GCN       用 SingleEncoderUNet，或设置 gcn_mode=none
  w/o Residual  --no-residual，图分支从零画图
  w/o AFM       把 --afm-mode 换成 concat 或 add
  SE 变体       --afm-mode se

 3. losses.py  —— 定目标（192 行）
--------------------------------------------------------------------------------

【它负责什么】
  定义「什么算预测对了」。整个文件只有两件事：
  一个损失函数，一个指标累加器。

【关键定义】

  行  36   _gaussian_window()     SSIM 用的高斯窗
  行  49   _ssim_components()     亮度/对比度/结构三项分量
  行  73   ms_ssim()              多尺度 SSIM（5 个尺度加权）
  行 106   class MFFGCNLoss       主损失
  行 113     __init__             l1=0.1, l2=1.0, l3=1e-4
  行 118     forward              返回 (总损失, 分项字典)
  行 139   nmse()                 归一化 MSE，逐图算再对 batch 平均
  行 151   rmse()
  行 157   class MetricAccumulator 全数据集精确累计
  行 171     reset
  行 178     update
  行 185     compute

【总损失公式】

  L = l1 * MSE(coarse, target)
    + l2 * MSE(fine,   target)
    + l3 * (1 - MS-SSIM(fine, target))

  默认权重：l1=0.1，l2=1.0，l3=1e-4

  三项各自的分工：

  第一项  粗估监督。让 U-Net 单独也学到东西，而不是全靠图分支兜底。
          权重只有 0.1，因为粗估本来就不要求多准。

  第二项  主项。最终输出的像素级误差，这一项决定 NMSE 指标。

  第三项  结构项。NMSE 是逐像素平方误差，会惩罚细节抖动、
          奖励模糊平滑的结果；MS-SSIM 补回结构相似度，
          让边缘和纹理不被抹平。1e-4 是量级系数，
          因为 MS-SSIM 的取值范围本身就是 0~1。

  为什么 coarse 也要监督：如果只监督 fine，
  图分支会独自承担全部重建任务，U-Net 退化成摆设；
  加了这一项，图分支才能只学「残差」这个更简单的目标。

【forward 返回分项字典的用途】
  返回 {"loss", "mse_coarse", "mse_fine", "ms_ssim_loss"}。
  日志里能分开看 coarse 和 fine 的 MSE，
  从而判断问题出在「粗估不行」还是「精修没修好」。
  排查时这一步能省很多时间。

【MetricAccumulator 为什么不能每 batch 平均】

  正确做法：只累加三个标量（误差平方和、真值平方和、元素个数），
  最后一次性相除。

  错误做法：每个 batch 算一次 NMSE 再取平均。
  这样小 batch 会被过度加权，最后一批不满时会系统性偏高。
  这是很多复现实验对不上论文数字的隐形原因之一，
  也是本文件里最容易被忽略、但直接影响可信度的一处。

  compute() 同时返回 nmse 与 nmse_coarse，
  两者相减就是图精修分支的净增益，不需要为此额外重跑模型。

 4. train.py  —— 跑流程（292 行）
--------------------------------------------------------------------------------

【它负责什么】
  把前面三者串成一次完整训练：解析参数 -> 建模型 -> 建数据 ->
  训练循环 -> 按验证集选 best -> 在测试集上出最终指标。

【关键定义】

  行  53   move()       把 batch 里的四份张量搬到 GPU
  行  61   fwd()        统一前向接口，兼容主模型与单编码器消融版
  行  74   evaluate()   在给定 loader 上算指标
  行 107   main()       全流程
  行 110-157             argparse 参数区（扫一眼即可，用时再查）

【训练循环里的四个关键动作】

  1. 混合精度（AMP）
     前向用 fp16，反向用 fp32 的 master weights。
     显存省一半、速度快一些，不损失精度。
     用 --no-amp 可以关掉，排查数值问题时用。

  2. 梯度裁剪
     阈值 5.0。防的是偶发的大梯度把参数一步打飞。
     图分支的 kNN 建图在早期不稳定，这一步是必要的保险。

  3. 早停与选 best
     每个 epoch 在验证集上算 NMSE，只保留最优的 best.pt。
     最终测试用的就是这份权重，不是最后一个 epoch 的权重。
     参数 --decay-epoch 控制学习率在第几轮衰减。

  4. 验证集只取前 60 个 batch
     --val-batches 默认 60。验证集全跑一遍要几分钟，
     50 个 epoch 加起来多花两三个小时。
     所以日志里的验证 NMSE 和最终测试 NMSE 会有微小差异，属正常。

【fwd() 为什么要做适配】

  主模型签名是 model(obs, env, mask) -> (coarse, fine, residual)
  单编码器消融版只有一条 U-Net，forward 只收一个张量。

  为了不给训练循环写两套解包逻辑，这里做了适配：

    y = model(torch.cat([obs, env], dim=1))
    return y, y, torch.zeros_like(y)

  coarse = fine = y，residual = 0。
  损失里那一项粗估监督，对单编码器就退化成对同一输出再算一遍，
  等价于不加权，不会引入偏差。

【evaluate() 为什么要算两套指标】

  acc    统计 fine，即最终输出
  acc_c  统计 coarse，把粗估同时当作预测值和最终值传进去

  目的只是单独取粗估那一份 NMSE。
  于是每个 run 的 test_metrics.json 里会同时留下
  nmse 和 nmse_coarse，两者相减就是 GCN 的净增益。

  另外 clamp(0,1) 不是可有可无的：
  fp16 下 sigmoid 加卷积偶尔会溢出到略大于 1，
  一个 1.02 的像素会让平方误差异常放大，指标直接错。
  显式裁剪是防止指标出错，不是为了让模型变好。

【常用参数】

  --setup s1|s2|s3      实验设置，见 dataset.py
  --arch mffgcn|single  主模型 / 单编码器消融
  --afm-mode            七种融合模式，见 models.py
  --gcn-layers          图传播层数，默认 3
  --k                   建图时的近邻数，默认 16
  --no-residual         消融：去掉残差连接
  --no-augment          关闭数据增广
  --subset-cities N     只用前 N 个城市训练（Fig.7 用）
  --tag                 实验名，决定 runs/<tag>/ 目录

【最小运行示例】

  cd /public2/czz/ZhangYu/project/mffgcn/src
  source /public2/czz/ZhangYu/activate_zhangyu.sh
  python train.py --cache ../data/cache --setup s1 --epochs 50 \
      --bs 32 --lr 1e-3 --tag my_test

  结果落在 runs/my_test/：best.pt 与 test_metrics.json

 附 C. 常见疑问
--------------------------------------------------------------------------------

  Q1  Pylance 把 GradScaler / autocast 标黄波浪线，是代码错了吗
  不是。torch 包太大，Pylance 索引没建全，属于误报。
  服务器实测可正常 import、可正常训练。
  处理：Ctrl+Shift+P -> Python: Restart Language Server。

  Q2  鼠标悬停显示 (parameter) obs: Unknown
  因为这几个函数都没写类型标注，Pylance 推断链断了。
  与代码正确性无关，只是编辑器读不出类型。

  Q3  test_metrics.json 里 nmse 和 nmse_coarse 有什么不同
  nmse 是最终输出（含图精修）的指标，nmse_coarse 是 U-Net 粗估的指标。
  两者相减即图精修的净增益，消融分析靠这一对数得出结论。

  Q4  日志里的验证 NMSE 和最终测试 NMSE 为什么对不上
  验证只跑前 60 个 batch（--val-batches），测试跑全量。
  这是为了省时间，属正常设计。

  Q5  参数量是多少
  MFFGCN 24.55 M，SingleUNet 7.76 M。
  5 层 GCN 版本 24.81 M（多 0.26 M）。

  Q6  想换实验条件该改哪个文件
  采样方式改 dataset.py；网络结构改 models.py；
  优化目标改 losses.py；训练策略改 train.py。
  四者互不越界，这是这套代码结构清晰的主要原因。
